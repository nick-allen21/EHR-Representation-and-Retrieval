\paragraph{Experimental Setup (first milestone run).}
We implemented an end-to-end prototype of our learned chunk selection layer and evaluated it on a held-out validation split. The model is trained to answer a binary question for each (question, chunk) pair: \emph{``Does this chunk contain evidence that helps answer this question?''} Concretely, we train an L1-regularized logistic regression model over a feature vector combining lexical similarity, embedding similarity, and simple structural/section interaction features. After training, the model produces a score for each chunk, which we use to rank chunks and select the top-$K$ under a budget.

\paragraph{Labeling (weak supervision).}
Training labels are derived automatically from the QA supervision. For each (question, answer, chunk) triple, we compute a token-level F1 overlap score between the \emph{answer text} and the \emph{chunk text} (treating each as a bag of alphanumeric tokens). A chunk is labeled \textbf{positive} if
\[
\mathrm{F1}(\text{answer}, \text{chunk}) \ge 0.15,
\]
and \textbf{negative} otherwise. This label is a proxy for answer evidence: the model never observes human relevance judgments, only this overlap-based signal. We will ablate the threshold (e.g., 0.10, 0.20, 0.30) in future work to study the tradeoff between missing weakly relevant evidence (too strict) and introducing noisy positives (too lax).

\paragraph{Validation protocol (leakage-safe).}
We follow patient-level splitting to prevent leakage: all examples from a given patient record (and its associated note text) are assigned entirely to train or validation. Feature extraction is also split-safe: the TF--IDF vocabulary is fit using \emph{train-only} texts (train questions + train chunks), and then applied to validation via \texttt{transform}. Sentence embeddings are computed using a frozen pretrained encoder and do not involve fitting on validation data. The logistic regression model is trained on train examples only and evaluated on held-out validation patients only. (At this milestone stage, we report validation performance; a separate test set will be introduced for the final evaluation.)

\paragraph{Metrics.}
We compute (i) \textbf{classification diagnostics} on the pooled validation (question, chunk) examples (ROC-AUC and average precision), and (ii) the primary retrieval metric: \textbf{per-question Recall@K}. For each validation question, we score all chunks from the associated note, select the top-$K$, and measure the fraction of positive (answer-supporting) chunks recovered. We then average Recall@K over all questions.

\paragraph{Preliminary results.}
On the validation set, the learned selector achieves strong retrieval performance under small budgets. The per-question Recall@K increases monotonically with $K$:
\[
\text{Recall@1}=0.45,\quad \text{Recall@3}=0.71,\quad \text{Recall@5}=0.84,\quad \text{Recall@10}=0.96.
\]
These results suggest the model ranks answer-containing chunks effectively: Recall improves sharply from $K{=}1$ to $K{=}5$, indicating that high-scoring chunks are preferentially relevant rather than the model simply classifying most chunks as negative.

\paragraph{Limitations of current results.}
These milestone results evaluate retrieval quality using overlap-derived ``positives'' as ground truth and report validation performance only. In the final report, we will (i) evaluate on clinician-reviewed QA benchmarks (e.g., EHRNoteQA) and (ii) compare a downstream small LLM baseline to the same model augmented with our learned retrieval layer, isolating gains attributable to improved context selection.
